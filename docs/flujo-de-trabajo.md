# Flujo de trabajo colaborativo

## Estado inicial
Al comenzar este scaffolding, `main` no tenía commits. `.gitignore`, `clases/` y `odd/` aparecían sin seguimiento. No se debe asumir un commit de base ni afirmar cuál es el historial remoto.

## Trabajo y Git
1. Revisá `git status --short --branch` y preservá los archivos sin seguimiento existentes.
2. Una vez que la persona autorice explícitamente establecer la línea base, acordá qué incluir y creá una rama de trabajo antes de la escritura sustancial. No des por hecho una rama base o historial remoto.
3. Revisá los cambios y prepará únicamente las rutas que correspondan a esa unidad de trabajo; no uses un staging indiscriminado.
4. Creá commits unitarios con formato Conventional Commits solo con autorización de la persona. No hagas commits automáticos.
5. No hagas push sin una decisión explícita. No infieras que existe un remoto o que su historial coincide con el local.
